Riftfall Arena — キャラクター個別化・運営長プレゼント／システムメール版

■ このZIPの構成
ZIPを開いた直下に index.html、main.js、data.js、assets、server があります。
外側のフォルダーを追加せず、このZIPをアップロードしてください。

■ キャラクター
・元から異なる外見を持つ20体はそのままです。
・同じ素体を使っていた209体に、個別の体格、頭部、髪・頭飾り、衣装、背面装備、武器形状を設定しました。
・実際の表示モデルを撮影した選択画像を209枚追加しました。色相フィルターだけの使い回しを解消しています。
・選択画面、パーティー編成、戦闘、物語フィールド、オンライン上の人物表示に反映します。
・軽量化のため、アニメーション用の骨格と元のGLBデータを共有し、表示時にキャラクター専用の形状を組み立てます。
・現在のゲームから参照されていなかった旧モデル3個だけを整理しています。

■ 運営長がプレゼントを送る
1. 「旅支度」で運営長の鍵を入力します。
2. タイトルの「プレゼント・メール配信」または運営長の間の送信ボタンを開きます。
3. 「プレゼント配信」で、全プレイヤー／プレイヤーID指定を選びます。
4. 件名・本文・灯晶の数、必要なら武器・防具を選びます。装備は合計10種類までです。
5. 期限と確認画面を確認して送信します。送信履歴で結果を確認できます。
相手がオフラインでも、サーバーに保存され、期限内に受信できます。
全員宛は、配信後に同期を設定した人も期限内に受け取れます。
宛先には受信箱に表示されるプレイヤーIDを使ってください。同期コードは秘密情報なので共有しないでください。
オンライン一覧の「贈る」「メール」からも相手を指定できます。
送信結果が不明な場合は同じ確認画面から再試行してください。送信識別子を保持し、重複配信を防ぎます。

■ システムメールを送る
「システムメール」タブで、宛先・件名・本文・期限を指定します。
プレゼントを付けない通知として送信できます。
件名は80文字、本文は2,000文字までです。

■ プレイヤーが受け取る
1. 受信するプレイヤーも、「旅支度」→「端末間の同期」で一度記録を預けてください。
2. タイトルの「受信箱」を開きます。自分のプレイヤーIDも確認できます。
3. メールを開き、プレゼントがある場合は受け取ります。
同じプレゼントの付与は1回だけです。通信が途切れた場合は同じメールで結果を確認できます。
灯晶の所持上限は999,999です。上限を超えるときは先に灯晶を使ってから受け取れます。
所持済みの装備は重複して増えず、灯晶にも換算しません。
プレゼントは戦闘を終えてから受け取ってください。未読・既読・受取済み・期限切れを表示します。
メールは50件ずつ読み込みます。未読バッジは読み込んだメール内の未読件数です。

■ 必須：配信機能を有効にするサーバー更新
ゲームのZIPの入れ替えだけでは、公開済みサーバーの処理は更新されません。
このZIPの server/worker.js と server/wrangler.toml を、現在使用中のCloudflare Workersへ反映してください。
今回追加した MAIL_STORE と v4-mail マイグレーションが必要です。
更新前は準備中の案内を表示し、送信・受け取りの成功を表示しません。
既存の署名鍵・PEPPER・秘密変数を作り直さず、既存の設定を引き継いでください。

手動更新：展開したフォルダーでターミナルを開き、次を順に実行します。
  cd server
  npm install
  npm run deploy

既存のGitHub Actionsを設定済みなら、server/・data.js・appearance-data.js を含めてリポジトリへ反映し、
「Deploy server」の成功を確認してください。実際に利用している公開先のオリジンを
server/wrangler.toml の ALLOWED_ORIGINS に設定する必要があります。
Rosebudのプレイ画面が別ホストのiframe内で動く場合は、その実際のオリジンを確認してください。
詳細は server/README.md の「6. 今回の更新」に記載しています。

この納品時点では、公開サーバーへのデプロイや、実際のプレイヤーへの配信は行っていません。
