# 双月のアルケイア — CG・操作品質改善

物語・オンライン・イベント共闘・無限天守・拠点攻城戦などを備えた従来のゲームを公開トップに戻し、同じエンジンを磨く版です。公開先は https://www.kasai-solutions-inc.com/ です。

## 今回の方針

`index.html` と `classic.html` は同じ従来ゲームを起動します。既存の戦士・固有技・所有状態・灯晶・同期コード・運営権限・サーバーAPIを引き継ぎ、独立した新しいゲームへの移行は行いません。`arkeia-save-v1` を含む既存の保存キーを継続使用します。

前回の新エンジン版は `rebirth.html` と `rebirth/` に保存しています。その説明は [保存版の説明](docs/REBIRTH.md) にあります。新エンジン版の別セーブを、従来版の通貨や進行へ自動変換しません。

## 品質改善

- 全モード・旅支度・クイックアクセスに独自の彫刻風SVGアイコンとCGイラストを配置。新しい双月の宮殿、氷晶洞窟の絵をタイトル・舞台選択・背景に使用し、設定画面も同じ意匠で統一。
- 通常キャラクターの実ジオメトリを画質に応じて細分化。UV、骨格のウェイト、モーフ、マテリアル区分を維持し、モデルごとの形状変更後に適用。キャッシュとポリゴン数には上限を設定。
- 斬撃の軌跡、詠唱の魔法陣、衝撃波、命中の光、投射物の軌跡、回復演出を戦闘の実際のアクションに連動。ダメージ判定や技の性能は変更せず、画質・端末・動きを減らす設定に応じて演出数を調整。
- 月庭、竹林、氷晶、砂漠、光廊、燠火、紫月の舞台に立体的な周辺装飾と空気感を追加。戦闘範囲外の建築物、曲面屋根、灯籠、鉱石、石材の表面を描き、城内・探索・横視点との切り替えでは不要な屋外装飾を隠す。
- タイトルの文字組みと背景画像の全面表示を修正。スマートフォンのモード一覧を読みやすい一列にし、メニュー移動・固定操作バーの余白を調整。
- お知らせとチャットをメニュー内の「旅人の広場」に配置し、チャットに明示的な閉じる操作を追加。
- 一人用の戦闘・探索中に画面を離れると自動で一時停止し、戻った後は手動で再開。オンラインの時間進行は継続。
- 自動マージ後、対象コミットの GitHub Pages 公開成功まで確認。

- 従来のモード・キャラクター選択・戦闘HUD・設定画面をPCとスマートフォン向けに調整。
- Three.js 0.184.0、glTF/Draco/Meshoptの読み込みを同梱ファイルに統一。戦闘の起動に外部3DライブラリCDNを必要としません。
- 既存のCG背景、GLBモデルとモーション、カメラ操作を維持しながら描画の安定性を改善。
- 戦闘終了・召喚解除時のリソース回収、モデル読み込み失敗時の探索復帰を改善。

## 画質の選択

「旅支度・設定」の画質から切り替えられます。

| 画質 | キャラクターの形状 | 舞台・戦闘の演出 |
| --- | --- | --- |
| 軽量 | 元モデルのまま | 大気粒子を省き、同時演出数を抑える |
| 標準 | 元モデルのまま | 表面の仕上げと標準量の演出 |
| 高画質 | 対象形状を1段階細分化（通常は三角形数4倍） | 精細な屋外装飾、豊かな粒子・光 |
| 最高CG | 対象形状を2段階細分化（通常は三角形数16倍） | 高画質以上の装飾。高性能PC向け |

すでに大規模なモデルや未対応の属性を持つ形状は、元の密度を維持します。細分化は画像テクスチャ自体の解像度を増やすものではありません。画質を下げると元の形状に戻り、使われなくなった生成ジオメトリを解放します。

CGの仕様・実測と新規画像の情報は [CG品質更新の記録](docs/CELESTIAL.md) にあります。

## 開発・確認

Node.js 22以上を使用します。

```sh
npm run dev
npm run check
npm test
npm ci --ignore-scripts
npx playwright install --with-deps chromium
npm run test:browser
```

`check` は従来版と保存している新エンジン版の構文・参照を確認し、CG用CSS・レジストリの画像参照と、モデル・演出モジュールの重複読み込みも検査します。

標準のブラウザテストは従来版を起動し、PC高画質とスマートフォン軽量画質でメニュー・選択・実際の3D戦闘・タッチ操作を確認します。アイコンと画像の表示、アクティブなモデルの三角形数、月庭と氷晶の舞台、実アクションによるエフェクト生成、終了時の解放を診断値でも確認します。最高CGの設定切り替えをUIで確認し、2段階細分化・スキニング・モーフ・資源上限はユニットテストで検証します。ブラウザのスクリーンショットと診断は Actions の `classic-smoke` artifact に保存されます。

CIから本番APIへの操作とWebSocketは遮断し、オンライン経済・運営アカウントを変更しません。オンライン機能の本番接続確認とは別の検証です。

保存版のブラウザ検証は `npm run test:rebirth` で個別に実行できます。

## mainへの自動反映

同一リポジトリの `codex/riftfall-*` ブランチから `main` への非下書きPRを作成すると、`Riftfall Quality` が検証成功後に自動マージし、GitHub Pagesの再ビルドを要求します。PR作成そのものは自動化していません。詳細は [自動反映の説明](docs/AUTOMATION.md) を参照してください。
